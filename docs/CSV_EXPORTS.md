# CSV 展示副本与原值证据

从 0.2.9 / 底稿格式 4 起，异常清单和源表 CSV 的字符串字段及表头若以
ASCII 或全角 `= + - @` 开始（包括前置空白），或以控制字符、BOM 开始，
会加上可见的 `text: ` 前缀。原本就以 `text: ` 开始的字符串再次加前缀，
防止它与处理后的另一个原值混淆。数值类型保持原数值，字符串中的 CR、LF、
逗号和引号按 CSV 规则引用，不能变成额外记录。

CSV 是便于表格查看的副本。`source_tables/*.json` 与 `reviews.json` 保留
原始字符串；证据关联和规则计算使用 JSON 原值。比如复核备注 `＝1+1`
在 CSV 中显示为 `text: ＝1+1`，在复核历史 JSON 中仍是 `＝1+1`。

旧的单引号方式没有覆盖全角触发字符，且部分电子表格软件重新保存后可能
移除转义。可见文本前缀提高了审阅时的可辨认性，但不保证所有表格软件、
导入设置或后续手工编辑都安全。参见 [OWASP CSV Injection](https://owasp.org/www-community/attacks/CSV_Injection)。

## 重放兼容

| 底稿格式 / 应用版本 | CSV 重放规则 | 复核证据关联 |
| --- | --- | --- |
| 2 / 0.2.7 | 原单引号策略 | 无，明确返回 `review_evidence_bound=false` |
| 3 / 0.2.8 | 原单引号策略 | 有 |
| 4 / 0.2.9 | 可见 `text: ` 策略，包含表头 | 有 |
| 5 / 0.2.10 | 同格式 4，时间线改用实际 UTC 顺序 | 有 |

格式号与应用版本必须匹配；校验器不能把旧 CSV 当成新策略处理。格式 2/3
只在校验旧底稿时使用历史序列化规则，新导出始终使用格式 5。
格式 2–4 仍按原字符串时间线重放，并明确报告旧排序；见[时间线与复核迁移](TIMELINE_ORDER.md)。
保留旧包原文件，再用当前源快照重新导出，可得到采用新 CSV 策略的副本；
不要手改旧包的清单、版本号或哈希。新导出不能补造未知的历史证据版本。

[实际 0.2.8 导出包的回归](../tests/test_csv_policy.py)保留并重放旧字节，
同时检查新备注原值、全角及控制字符、前缀碰撞、数值与多行记录边界。
